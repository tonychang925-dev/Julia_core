# Create a Voice Provider

> **What you'll build**: A voice provider that gives your agent speech output  
> **Time**: ~30 minutes  
> **Prerequisites**: [Build Your First Agent](BUILD_YOUR_FIRST_AGENT.md)

---

## What is a Voice Provider?

A Voice Provider renders **audio bytes** from text + emotion + prosody metadata. It does NOT decide emotion, modify persona, or access memory.

```
Voice OS (Core)
    │
    ├── CognitiveEmotion    "Julia feels warm"
    ├── ProsodyPlanner      "warm → speed 0.85, pitch +3Hz"
    │
    ▼
VoiceRenderRequest(text, emotion, metadata)
    │
    ▼
VoiceProvider (YOU)
    │
    ├── Accept: text + emotion + prosody parameters
    ├── Render: audio bytes via TTS engine
    └── Return: bool (speak) or bytes (synthesize)
```

---

## The VoiceProvider Contract

```python
class VoiceProvider(Protocol):
    provider_id: str

    def speak(self, text: str, *, emotion: CognitiveEmotion | None = None, metadata: SpeechMetadata | None = None) -> bool:
        """Synthesize and play audio. Returns True on success."""
        ...

    def synthesize(self, text: str, *, emotion: CognitiveEmotion | None = None, metadata: SpeechMetadata | None = None) -> bytes | None:
        """Synthesize audio, return raw bytes. Returns None on failure."""
        ...
```

### Input: SpeechMetadata

Generated by Core's `SpeechProsodyPlanner`:

```python
SpeechMetadata(
    speed=0.85,        # 0.5 - 2.0
    pitch_shift="+3Hz",  # e.g. "+3Hz", "-5%"
    pause_ms=300,      # pause between sentences
    energy=0.7,        # 0.0 - 1.0
)
```

### Input: CognitiveEmotion

Generated by Core's Voice OS:

```python
CognitiveEmotion(
    state=EmotionState.WARM,   # One of 8 emotion states
    intensity=0.7,             # 0.0 - 1.0
)
```

## Step-by-Step

### Step 1: Create your provider

```python
# my_providers/my_tts_provider.py
from julia_core.voice_os.emotion_state import CognitiveEmotion, EmotionState
from julia_core.voice_os.prosody import SpeechMetadata


class MyTTSProvider:
    provider_id = "my_tts_v1"

    def speak(self, text: str, *, emotion: CognitiveEmotion | None = None, metadata: SpeechMetadata | None = None) -> bool:
        """Render text → audio and play."""
        audio = self.synthesize(text, emotion=emotion, metadata=metadata)
        if audio is None:
            return False
        self._play_audio(audio)
        return True

    def synthesize(self, text: str, *, emotion: CognitiveEmotion | None = None, metadata: SpeechMetadata | None = None) -> bytes | None:
        """Render text → audio bytes."""
        # Apply prosody parameters to your TTS engine
        prosody = metadata or SpeechMetadata()

        # Your TTS engine call here
        audio_bytes = self._call_tts_engine(
            text=text,
            speed=prosody.speed,
            pitch=prosody.pitch_shift,
        )
        return audio_bytes

    def _call_tts_engine(self, text: str, speed: float, pitch: str) -> bytes:
        """Replace with your TTS API call."""
        # Example: EdgeTTS, ElevenLabs, Fish Audio, local model
        # See providers/examples/voice/ for reference
        return b""

    def _play_audio(self, audio: bytes) -> None:
        """Platform-specific audio playback."""
        pass
```

### Step 2: Register your provider

```python
from julia_core.providers.registry import ProviderRegistry

registry = ProviderRegistry()
registry.register(MyTTSProvider())
```

### Step 3: Use with Voice OS

```python
from julia_core.voice_os.emotion_state import CognitiveEmotion, EmotionState
from julia_core.voice_os.prosody import SpeechProsodyPlanner

# Core decides emotion
emotion = CognitiveEmotion(state=EmotionState.EXCITED, intensity=0.9)

# Core plans prosody
planner = SpeechProsodyPlanner()
metadata = planner.plan(emotion)
# → SpeechMetadata(speed=1.02, pitch_shift="+10Hz", pause_ms=200, energy=0.82)

# Your provider renders
provider = MyTTSProvider()
provider.speak("That's amazing news!", emotion=emotion, metadata=metadata)
```

## Emotion → Prosody Reference

Your provider doesn't need to implement this mapping — Core does it. But here's what you receive:

| Emotion | Speed | Pitch | Pause | Energy |
|---------|-------|-------|-------|--------|
| WARM | 0.85 | +3Hz | 300ms | 0.60 |
| THINKING | 0.72 | -5Hz | 500ms | 0.70 |
| CONFIDENT | 0.88 | +5Hz | 350ms | 0.80 |
| EXCITED | 1.05 | +10Hz | 200ms | 0.90 |
| SOFT | 0.75 | -3Hz | 400ms | 0.40 |
| CONCERNED | 0.78 | -2Hz | 450ms | 0.55 |
| PLAYFUL | 0.95 | +8Hz | 250ms | 0.75 |
| NEUTRAL | 0.82 | +0Hz | 300ms | 0.60 |

Intensity (0.0–1.0) interpolates between neutral and the full emotion value.

## Provider Rules

### ✅ Your Provider MUST

| Rule | Why |
|------|-----|
| Accept `(text, emotion, metadata)` | Standard input contract |
| Return `bool` from `speak()` | Success/failure for routing/fallback |
| Return `bytes | None` from `synthesize()` | Audio data or explicit failure |
| Handle `emotion=None` gracefully | Default to neutral |
| Register via ProviderRegistry | Standard lifecycle |

### ❌ Your Provider MUST NOT

| Rule | Why |
|------|-----|
| Analyze text for emotion | Core's CognitiveEmotion is the authority |
| Override prosody decisions | Core's ProsodyPlanner owns the mapping |
| Access memory | Voice has no memory access path |
| Modify context | Voice is output-only |
| Choose voice character | Voice profile is persona-level concern |

## Anti-Patterns

### ❌ Provider Decides Emotion

```python
# DO NOT DO THIS
class BadTTS:
    def speak(self, text):
        if "love" in text:
            emotion = "romantic"  # Not in Core's emotion taxonomy!
        elif "sad" in text:
            emotion = "mournful"
        return self.render(text, emotion)
```

**Correct**: Accept `emotion: CognitiveEmotion` from Core. Don't analyze text.

### ❌ Provider Selects Voice Character

```python
# DO NOT DO THIS
class BadTTS:
    def speak(self, text, emotion, metadata):
        # Provider decides to use a different voice
        voice = "sexy_female_voice" if emotion.state == EmotionState.WARM else "default"
        return self.render(text, voice=voice)
```

**Correct**: Voice character is a persona/profile concern. Provider renders with the configured voice.

## VoiceProvider vs DomainProvider

Same pattern, different output:

```
Domain Provider:  ContextRequest → ContextBlock (facts)
Voice Provider:   text + emotion + metadata → audio bytes

Both: supply CAPABILITY, not COGNITION
Both: registered in ProviderRegistry
Both: pluggable without Core changes
```
